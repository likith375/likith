Import training material

Drop supported files such as .py, .js, .ts, .ipynb, .jsonl, .json, .csv, .lua, .luau, .txt or .md into data/examples/ or data/inbox/ and import them in one click. Recommended fields: prompt, content (or code), category, split. Maximum 15 MB per file. Supports JSONL, JSON, CSV, TXT, Markdown, Python, JavaScript, TypeScript, C/C++, Java, C#, Go, Rust, SQL, shell scripts, Lua/Luau, Jupyter notebooks, selectable-text PDF, DOCX, XLSX spreadsheets, and PPTX presentations. Long documents are chunked into training references.

Review model attempts

Rate answers from 1–5. Ratings 1–2 provide negative reward, 4–5 positive reward, and 3 is neutral. Corrections remain unverified until reviewed in Mistake memory.

Export feedback ↗
How your feedback is used

Ratings are queued for reward training. NeuralForge marks a rating as consumed only after the adapter reports a real reward update and a post-training checkpoint is saved. A rating alone does not guarantee a weight change.

OPTIMIZATION

Training runs

Run actual reward-based fine-tuning through your connected adapter.

Training prerequisites

A working model adapter is required. The built-in Hugging Face REINFORCE adapter performs real policy-gradient updates but uses static heuristic rewards. It is an experimental baseline, not a guarantee of code correctness. Set a time budget up to 24 hours and a high episode cap for long sessions; your computer or Codespace must remain running.

HELD-OUT TESTING

Evaluation bench

Measure generalization on validation and test examples without updating model weights.

Keep the test set clean

Use validation benchmarks during development. Run the test benchmark only when you want a final held-out check. Scores use the configured domain evaluator when available; otherwise they are labelled static heuristics and do not prove factual or runtime correctness.

Adapter contract

  1. generate(prompt, context)Return generated text for the requested subject.
  2. train_step(batch)Perform a real optimizer update using response rewards.
  3. save_checkpoint(path)Persist model weights and optimizer state.
  4. load_checkpoint(path)Restore the saved model state.
